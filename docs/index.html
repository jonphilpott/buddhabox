BuddhaBox

A modular DSP framework for generative ambient audio on STM32

Architecture

BuddhaBox is a sample-by-sample modular DSP framework. Every sound-producing or sound-shaping module exposes a float process() method that returns one audio sample at a time. You compose patches by wiring outputs into inputs — just like patching a modular synthesizer with cables.

Signal Flow

The audio engine uses I2S DMA double-buffering. The DMA hardware continuously streams samples to the DAC. When it finishes one half of the buffer, it fires an interrupt and your audioCallback() fills that half with fresh samples while the other half plays.

Your DSP Code → audioCallback() → DMA Buffer → I2S Peripheral → UDA1334A DAC → Audio Out

Design Principles

Principle What It Means
Sample-by-sample Every module processes one sample per call. No block sizes to worry about when patching modules together.
Float internal, int16 output All DSP math uses float (-1.0 to +1.0). Conversion to 16-bit integers only happens at the final output stage.
Header-only modules DSP modules are defined entirely in .h files so the compiler can inline critical functions. Only the audio engine has a .cpp.
No dynamic allocation All memory is allocated at compile time via global objects and template parameters. No new or malloc in the audio path.
Composable Any module's output can feed into any other module's input. An LFO can modulate a filter, which filters an oscillator, which is shaped by an envelope.
Control-rate separation Slowly-changing modulators (LFOs, envelopes) can run at a fraction of audio rate via LFO::setDivider(n). Combined with lazy coefficient caching in SVFilter::setFrequency(), this reduces the dominant per-sample cost (transcendental math) by up to 64×.

Oscillator oscillator.h

Class: Oscillator

Audio-rate waveform generator using the phase accumulator pattern. A phase variable ramps 0→1 at a rate determined by frequency, and the current phase is transformed into the selected waveform shape. Sine uses a 512-entry pre-computed wavetable with linear interpolation (shared across all Oscillator instances, initialized once at startup). SAW, SQUARE, and TRIANGLE use direct math formulas — they are already optimal at 1–3 float operations each.

LFO lfo.h

Class: LFO

Low Frequency Oscillator for modulating parameters over time (filter cutoff, amplitude, pitch, delay time). Same waveform math as Oscillator but intended for sub-audio rates (0.01–20 Hz). Always outputs -1.0 to +1.0 (no amplitude parameter) — scale the output to the target range using mapf().

For slow LFOs (<5 Hz), use setDivider(n) to run the LFO at a fraction of audio rate. This reduces the LFO's CPU cost by n× and — because the held value is fed into SVFilter::setFrequency() — also eliminates redundant sinf() calls in the filter, which is the dominant cost of LFO-modulated filter sweeps.

Instantiation

LFO lfo;  // Default: 1 Hz sine

Methods

void setFrequency(float hz)
Set the LFO rate.
hz — float — frequency in Hz. 0.05 = 20s cycle, 0.15 = ~7s, 1.0 = 1s, 5.0 = vibrato speed.
void setWaveform(Waveform w)
Set waveform shape. SINE = smooth sweep, TRIANGLE = linear, SAW = ramp up + snap, SQUARE = toggle.
w — Waveform — one of SINE, SAW, SQUARE, TRIANGLE
void setDivider(uint32_t n)
Run the LFO at 1/n of audio rate (control-rate downsampling). The LFO recomputes its waveform only once every n audio samples, holding the cached value in between. The internal phase still advances by the correct amount per fire, so LFO frequency stays exact. Inaudible for LFOs below ~5 Hz with n up to 256.

Why this matters: LFOs typically drive SVFilter::setFrequency(), which calls sinf() to recompute a coefficient. With setDivider(64), that sinf() cost drops 64×. Combined with SVFilter's frequency caching (see below), per-sample filter updates become nearly free.
n — uint32_t — samples between recomputations. 1 = every sample (default). Practical values:
16 = ~2756 Hz control rate — fine for vibrato up to ~5 Hz
64 = ~689 Hz control rate — recommended for filter/delay LFOs
256 = ~172 Hz control rate — fine for LFOs below ~0.5 Hz
float process()
Generate the next LFO sample. Call once per audio sample. If a divider is set, returns the cached value on non-recompute samples — transparent to the caller.
Returns: float in [-1.0, +1.0]
void reset()
Reset phase to zero and rearm the divider counter so the very next process() call recomputes at phase 0 (rather than returning a stale cached value). Useful for syncing LFO to a tempo clock.
float getPhase() const
Returns: float — current phase 0.0–1.0
void setPhase(float p)
p — float — phase position 0.0–1.0
LFO filterSweep;
filterSweep.setWaveform(Waveform::TRIANGLE);
filterSweep.setFrequency(0.1f);   // One cycle every 10 seconds
filterSweep.setDivider(64);      // Recompute at ~689 Hz — imperceptible at 0.1 Hz

// In audio callback (unchanged — setDivider is transparent to the caller):
float mod = filterSweep.process();
float cutoff = mapf(mod, -1.0f, 1.0f, 200.0f, 3000.0f);
filter.setFrequency(cutoff);  // SVFilter caches this; sinf() only runs when cutoff changes

// Sync LFO to tempo (reset() also rearmes the divider counter):
if (clock.process()) {
    filterSweep.reset();  // Restart from phase 0 on each beat
}

SVFilter filter.h

Class: SVFilter

Chamberlin State Variable Filter providing simultaneous lowpass, highpass, and bandpass outputs from a single process() call. Resonance creates a peak at the cutoff frequency; at maximum, the filter self-oscillates. Cutoff clamped to sampleRate/4 for stability.

Instantiation

SVFilter filter;  // Default: 1000 Hz cutoff, no resonance

Methods

void setFrequency(float hz)
Set the cutoff frequency. Internally calls sinf() to recompute the filter coefficient — but only when the frequency has actually changed. Repeated calls with the same value (e.g., from a downsampled LFO holding its output for 64 samples) are detected by exact float comparison and return immediately with no computation. This makes it safe to call setFrequency() every audio sample without paying the sinf() cost on idle cycles.
hz — float — cutoff in Hertz. 20 = very dark, 1000 = warm, 5000 = bright. Clamped to [20, SAMPLE_RATE/4] for stability.
void setResonance(float q)
Set filter resonance.
q — float — 0.0 = no resonance, 0.5 = classic synth, 0.9 = strong ringing, 1.0 = self-oscillation. Clamped to [0.0, 1.0].
void process(float input)
Process one input sample. After calling, read outputs via lowpass()/highpass()/bandpass().
input — float — input sample, typically -1.0 to +1.0
float lowpass() const
Returns: float — lowpass output (frequencies below cutoff)
float highpass() const
Returns: float — highpass output (frequencies above cutoff)
float bandpass() const
Returns: float — bandpass output (frequencies near cutoff)
void clear()
Reset all internal state to zero. Use when changing patches.
SVFilter filter;
filter.setFrequency(800.0f);
filter.setResonance(0.4f);

// In audio callback:
filter.process(inputSample);
float warm = filter.lowpass();
float bright = filter.highpass();
float focused = filter.bandpass();
float notch = filter.lowpass() + filter.highpass();  // Notch filter!

MoogFilter moog_filter.h

Class: MoogFilter

Approximation of the classic Moog ladder filter — four one-pole lowpass stages in series with resonance feedback and a nonlinear input stage. Produces a 24 dB/octave rolloff with warm, saturated character. At maximum resonance the filter self-oscillates, producing a pitched sine wave at the cutoff frequency.

Signal Flow

input → softclip(x − k·s[3]) → [stage 0] → [stage 1] → [stage 2] → [stage 3] → output ↑ │ └────────── k × feedback ─────────────────┘

MoogFilter vs SVFilter

Property MoogFilter SVFilter
Rolloff slope 24 dB/octave (4-pole) 12 dB/octave (2-pole)
Output modes Lowpass only LP + HP + BP simultaneously
Character Warm, nonlinear, saturated Clean, linear
Self-oscillation Yes (bounded by softclip) Yes (at q = 1.0)
Frequency coeff expf() once in setFrequency() sinf() once in setFrequency()

Instantiation

MoogFilter filter;  // Default: 1000 Hz cutoff, no resonance

Methods

void setFrequency(float hz)
Set the cutoff frequency. Internally calls expf() to compute the one-pole coefficient g = 1 - e^(-2πfc/fs) — but only when the value has changed. Repeated calls with the same frequency (e.g., from a downsampled LFO) are detected by exact float comparison and skipped, making it safe to call every sample.
hz — float — cutoff in Hertz. Clamped to [20, SAMPLE_RATE × 0.45].
void setResonance(float res)
Set filter resonance. Internally maps [0.0, 1.0] to a feedback gain k in [0.0, 3.99]. At k = 4 the filter would oscillate indefinitely; the nonlinear input stage keeps it bounded.
res — float — 0.0 = clean lowpass, 0.5 = classic Moog warmth, 0.8 = strong ringing, 1.0 = self-oscillation. Clamped to [0.0, 1.0].
float process(float input)
Process one input sample. Applies feedback subtraction, the softclip nonlinearity, and four cascaded one-pole stages. Call exactly once per sample in the audio callback.
input — float — input sample, typically -1.0 to +1.0
Returns: float — lowpass-filtered output sample
void clear()
Reset all four stage states to zero. Use when switching patches to avoid clicks from residual filter energy.
MoogFilter filter;
filter.setFrequency(800.0f);
filter.setResonance(0.6f);

// In audio callback — classic Moog sweep:
float saw = osc.process();
float out = filter.process(saw);

// Modulate cutoff with an LFO for a filter sweep:
float mod = lfo.process();
filter.setFrequency(mapf(mod, -1.0f, 1.0f, 80.0f, 6000.0f));

// Self-oscillate as a sine wave source — no input needed!
filter.setResonance(1.0f);
filter.setFrequency(220.0f);   // Pitch = 220 Hz (A3)
float sine = filter.process(0.0f);  // Feed silence, get sine

Convert MIDI note to frequency. Formula: 440 * 2(note - 69) / 12
noteNumber — uint8_t — MIDI note 0–127. Middle C = 60, Concert A = 69.
Returns: float — frequency in Hz

Note Constants

NOTE_C124C132.7 Hz

NOTE_C348C3130.8 Hz

Composing New Modules

The BuddhaBox framework is designed to be composable: you build complex sounds by wiring simple modules together. Here's how to create your own reusable composite modules from the building blocks.

Pattern: Wrap Modules in a Class

The simplest approach is to create a class that holds the modules you need as members and exposes a process() method. This encapsulates the signal routing and parameter management.

Example: Filtered Oscillator

An oscillator with a built-in filter and LFO-modulated cutoff:

class FilteredOsc {
public:
    void setNote(uint8_t note) {
        osc_.setFrequency(midiToFreq(note));
    }

    void setFilterRange(float lo, float hi) {
        filterLo_ = lo;
        filterHi_ = hi;
    }

    void setLFORate(float hz) {
        lfo_.setFrequency(hz);
    }

    float process() {
        // LFO sweeps the filter cutoff
        float mod = lfo_.process();
        float cutoff = mapf(mod, -1.0f, 1.0f, filterLo_, filterHi_);
        filter_.setFrequency(cutoff);

        // Oscillator through filter
        filter_.process(osc_.process());
        return filter_.lowpass();
    }

private:
    Oscillator osc_;
    SVFilter filter_;
    LFO lfo_;
    float filterLo_ = 200.0f;
    float filterHi_ = 3000.0f;
};

Example: Enveloped Voice

A complete synth voice with oscillator + envelope + filter:

class SynthVoice {
public:
    void noteOn(uint8_t note) {
        osc_.setFrequency(midiToFreq(note));
        env_.gate(true);
    }

    void noteOff() { env_.gate(false); }

    bool isActive() { return env_.isActive(); }

    float process() {
        return osc_.process() * env_.process();
    }

private:
    Oscillator osc_;
    Envelope env_;
};

Example: Echo Unit

A reusable delay effect with controllable time and feedback:

class EchoUnit {
public:
    void setTime(float samples) { time_ = samples; }
    void setFeedback(float fb) { feedback_ = clampf(fb, 0.0f, 0.95f); }
    void setMix(float wet) { wet_ = wet; }

    float process(float input) {
        float delayed = delay_.read(time_);
        delay_.write(input + delayed * feedback_);
        return input * (1.0f - wet_) + delayed * wet_;
    }

private:
    DelayLine<8192> delay_;
    float time_ = 4000.0f;
    float feedback_ = 0.4f;
    float wet_ = 0.3f;
};

Key Principles

  • process() returns float: Keep the same pattern as built-in modules. Input and output are always float samples in [-1.0, +1.0].
  • Members not pointers: Declare sub-modules as member variables (not pointers). This avoids dynamic allocation and the compiler can inline method calls.
  • One sample at a time: Your process() should compute exactly one output sample per call, calling each sub-module's process() exactly once.
  • Expose only what's needed: Don't pass through every sub-module parameter. Expose high-level controls that make sense for the composite (e.g., noteOn instead of separate setFrequency + gate).
  • Watch your RAM: Each DelayLine uses significant RAM. Be mindful when composing modules that contain delay lines — check your build stats with pio run.

A. D Major Arpeggio — Plucked Sine

A simple sequencer that cycles through D–F#–A–D (D major triad over one octave) at 140 BPM eighth notes. Each note is shaped by a short envelope to create a plucked, bell-like quality.

TempoClock (140 BPM, eighths) → triggers Envelope → selects note Oscillator (sine) × Envelope → Output
// ── Example A: D Major Arpeggio with Plucked Sine ──

#include "audio_engine.h"
#include "oscillator.h"
#include "envelope.h"
#include "clock.h"
#include "midi_utils.h"

Oscillator osc;
Envelope env;
TempoClock clock(140.0f, 2);  // 140 BPM, eighth notes

// D major arpeggio: D4, F#4, A4, D5
const uint8_t arpeggio[] = {
    NOTE_C4 + 2,   // D4  (MIDI 62)
    NOTE_C4 + 6,   // F#4 (MIDI 66)
    NOTE_C4 + 9,   // A4  (MIDI 69)
    NOTE_C5 + 2    // D5  (MIDI 74)
};
const int arpLen = 4;

void audioCallback(int16_t* buffer, uint16_t length) {
    for (uint16_t i = 0; i < length; i += 2) {

        // On each clock tick, advance to the next arpeggio note
        if (clock.process()) {
            int step = clock.getTick() % arpLen;
            osc.setFrequency(midiToFreq(arpeggio[step]));
            env.trigger();  // Percussive: auto-releases after attack
        }

        // Sine oscillator shaped by the envelope
        float sample = osc.process() * env.process() * 0.6f;

        int16_t s = (int16_t)(clampf(sample, -1.0f, 1.0f) * 32000.0f);
        buffer[i]     = s;
        buffer[i + 1] = s;
    }
}

void setup() {
    osc.setWaveform(Waveform::SINE);  // SINE uses the 512-entry wavetable
    osc.setAmplitude(1.0f);
    env.setAttack(0.002f);    // 2 ms — sharp pluck
    env.setRelease(0.3f);     // 300 ms — bell-like decay
    AudioEngine::begin();
}

void loop() { delay(10); }

B. Rain Simulation

Layered filtered noise that sounds like rainfall. Two pink noise sources are filtered at different frequencies: a low rumble (distant thunder/heavy drops) and a high patter (light rain on a surface). An LFO slowly modulates the high layer's brightness, simulating gusts of wind.

PinkNoise 1 → SVFilter (LP 300 Hz) → ╮ ├→ Mix → Output PinkNoise 2 → SVFilter (LP, swept) → ╯ ↑ LFO (tri, 0.07 Hz)
// ── Example B: Rain Simulation ──

#include "audio_engine.h"
#include "noise.h"
#include "filter.h"
#include "lfo.h"

PinkNoise rainLow(11111);
PinkNoise rainHigh(22222);
SVFilter filterLow;
SVFilter filterHigh;
LFO gustLFO;

void audioCallback(int16_t* buffer, uint16_t length) {
    for (uint16_t i = 0; i < length; i += 2) {
        // Layer 1: Low rumble
        filterLow.process(rainLow.process() * 0.4f);
        float rumble = filterLow.lowpass();

        // Layer 2: High patter — filter swept by LFO
        float cutoff = mapf(gustLFO.process(), -1.0f, 1.0f, 1500.0f, 6000.0f);
        filterHigh.setFrequency(cutoff);
        filterHigh.process(rainHigh.process() * 0.25f);
        float patter = filterHigh.lowpass();

        float rain = rumble + patter;
        int16_t s = (int16_t)(clampf(rain, -1.0f, 1.0f) * 32000.0f);
        buffer[i]     = s;
        buffer[i + 1] = s;
    }
}

void setup() {
    filterLow.setFrequency(300.0f);
    filterLow.setResonance(0.2f);
    filterHigh.setFrequency(3000.0f);
    filterHigh.setResonance(0.1f);
    gustLFO.setWaveform(Waveform::TRIANGLE);
    gustLFO.setFrequency(0.07f);
    gustLFO.setDivider(64);   // 0.07 Hz — run at ~689 Hz control rate
    AudioEngine::begin();
}

void loop() { delay(10); }

C. Tanpura-like Drone

A tanpura produces a shimmering, harmonically rich drone by plucking four strings that ring continuously. This version uses the KarplusStrong class. Four strings tuned to Pa–Sa–Sa–Sa (A3–D4–D4–D3) are re-plucked in sequence by a slow tempo clock.

TempoClock (50 BPM) → cycles through 4 strings, re-plucks each KarplusStrong[0] (A3) → ╮ KarplusStrong[1] (D4) → ├→ Mix → softclip → Output KarplusStrong[2] (D4) → ┤ KarplusStrong[3] (D3) → ╯
// ── Example C: Tanpura-like Drone using KarplusStrong ──

#include "audio_engine.h"
#include "karplus.h"
#include "clock.h"
#include "midi_utils.h"

KarplusStrong<1024> strings[4] = {
    KarplusStrong<1024>(111),  // Different seeds per string
    KarplusStrong<1024>(222),
    KarplusStrong<1024>(333),
    KarplusStrong<1024>(444)
};

TempoClock pluckClock(50.0f, 1);  // Slow, meditative

// Tanpura tuning: Pa, Sa, Sa, low Sa
const uint8_t tuning[] = {
    NOTE_C4 + 9,   // A3 — Pa (the fifth)
    NOTE_C4 + 2,   // D4 — Sa (the tonic)
    NOTE_C4 + 2,   // D4 — Sa (doubled)
    NOTE_C3 + 2    // D3 — low Sa
};

void audioCallback(int16_t* buffer, uint16_t length) {
    for (uint16_t i = 0; i < length; i += 2) {

        if (pluckClock.process()) {
            int which = pluckClock.getTick() % 4;
            strings[which].pluck(midiToFreq(tuning[which]));
        }

        float mix = 0.0f;
        for (int s = 0; s < 4; s++) {
            mix += strings[s].process() * 0.3f;
        }

        // Soft clip for gentle warmth
        mix = softclip(mix, 1.5f);

        int16_t out = (int16_t)(clampf(mix, -1.0f, 1.0f) * 32000.0f);
        buffer[i]     = out;
        buffer[i + 1] = out;
    }
}

void setup() {
    // Pluck all strings at startup
    for (int i = 0; i < 4; i++) {
        strings[i].pluck(midiToFreq(tuning[i]));
    }
    AudioEngine::begin();
}

void loop() { delay(10); }
Tip: To make the tanpura sound more authentic, try adding a very subtle pitch bend by slowly modulating the delay time with an LFO (±0.5 samples). Real tanpura strings have a characteristic "jivari" buzz caused by the string grazing the bridge — you can approximate this by increasing the damping slightly and using softclip() with a higher drive value.

Speaker Enclosure Guide

To get the best "warmth" for your ambient drones from small 3W/5W speakers, the enclosure design is just as important as the DSP code. For small, full-range drivers, a Sealed Enclosure is almost always the best choice—it provides a smooth bass roll-off and protects the speaker from over-excursion.

Optimal Acoustic Ratios

To prevent "boxy" resonances, avoid a Perfect Cube (all dimensions equal) and avoid simple integer ratios between dimensions (e.g., 1:1:2 or 1:2:2) — these cause multiple standing-wave modes to stack on the same frequency. The commonly cited 1 : 1.25 : 1.6 ratio is a reasonable starting point, but its origin is room acoustics (Volkman, 1942), not speaker enclosure design. For a 0.75 L box whose longest internal dimension is around 11 cm, the lowest-order standing wave occurs at approximately 343 m/s ÷ (2 × 0.11 m) ≈ 1560 Hz — well above the bass range where box tuning matters. At these enclosure sizes, the precise ratio values have little audible effect; any non-equal, non-harmonic set of dimensions is adequate. The standing waves that do form above 1 kHz are far more effectively controlled by interior wall damping (see below) than by dimensional ratios.

Internal Dimension Recommendations

Note: These are internal measurements. Add your material thickness to get external size — e.g., 6 mm per side for MDF, or 4–6 mm per side for 3D print. The volumes below are rough starting estimates only.

T/S Parameters: The correct sealed box volume depends on your driver's Vas (acoustic compliance volume) and Qts (total Q). Without measuring these, any volume recommendation is a rough guess. The formula is: Vb = Vas / ((Qtc / Qts)2 − 1), where Qtc = 0.707 gives a maximally flat Butterworth response. For an unknown cheap 2″ driver, Vas is typically 0.2–0.5 L, so 0.3–0.5 L is a more conservative starting estimate than the 0.75 L below. A box that sounds boomy is too large (Qtc too low); one that sounds thin has too-high Qtc or a naturally high Fs driver. Stuffing lets you experiment with effective volume before cutting final dimensions.

Advanced Tuning Tips

  • Slanted Back Wall: Tilting the rear wall by 5–10° disrupts the parallel front/back surfaces that produce flutter echo. In larger enclosures (>5 L) this is a meaningful improvement. For the sub-2 L boxes here, the same standing waves occur above 1.5 kHz and are more cost-effectively addressed by lining the rear wall with acoustic foam. Still worth doing if your geometry allows it.
  • Baffle Off-Centering: Don't mount the driver exactly in the center of the front face. Shifting it 5–10 mm off-center (both horizontally and vertically) spreads diffraction artifacts from the baffle edges across a wider frequency range rather than concentrating them at one frequency.
  • Interior Wall Damping (lining): Glue 5–10 mm open-cell acoustic foam or felt to all interior walls. This is the primary treatment for the mid/high-frequency standing waves that form above ~1.5 kHz inside these small enclosures. It works by acoustic absorption — the porous surface converts reflected sound energy into heat. Do this first, before stuffing.
  • Volume Stuffing: After lining the walls, loosely fill one-third to one-half of the remaining air volume with poly-fill or Dacron batting. This works by a completely different mechanism from wall damping: the fibres act as a thermal reservoir, slowing heat exchange during compression and shifting the air's behaviour toward isothermal. The result is a lower effective air-spring stiffness — acoustically equivalent to a larger box. Poly-fill typically increases effective volume by 20–30%; dense long-fibre fiberglass batting can approach the theoretical ceiling of ~40%. Do not over-stuff — packing the material too tightly reduces airflow and can actually increase low-frequency damping, which counteracts the volume-increase benefit.
  • Airtight Seal: 100% airtight is critical for sealed boxes. The sealed air acts as a spring; any leak bypasses it, softening bass and potentially causing rattles. Use hot glue or silicone around the driver rim, wire pass-throughs, and all panel joints.

Material Choice

  • Wood (MDF/Plywood): 6 mm (1/4″) is a practical minimum for a sub-1 L box. MDF is preferred over plywood for acoustics — it is denser and more homogeneous, which reduces panel resonance. Both are naturally more damping than plastic and produce a warmer tone.
  • 3D Printed: 4 perimeters at a 0.4 mm nozzle = 1.6 mm, which is too thin for an acoustic enclosure. Thin walls flex and rattle, acting like a secondary speaker cone. Aim for 4–6 mm wall thickness (10–15 perimeters), plus 20–40% gyroid or honeycomb infill. Gyroid infill is preferred over rectilinear because it creates non-parallel internal surfaces that scatter standing waves rather than reinforcing them. PLA is adequate and stiff; PETG is tougher and slightly more damping but more flexible, which can allow wall vibration in thin sections — keep walls thick if using PETG.
Passive Radiators: A passive radiator (a speaker cone with no motor) can extend bass response beyond what a sealed box achieves, and avoids the port-length problem that makes bass-reflex designs impractical in small enclosures. They are used across a wide range of sizes, from tiny Bluetooth speakers to large subwoofers. However, they require deliberate tuning: the tuning frequency is set by the passive radiator's moving mass and the enclosure volume (Fp = (1/2π) × √(Kbox / Mpr)). You adjust it by adding adhesive mass (putty, lead tape) to the passive radiator cone to lower Fp. Without matching it to your driver and target frequency, it will not perform correctly — and without T/S parameters for the active driver, calculating the correct tuning is an iterative process. Treat this as a weekend experimentation project, not a drop-in improvement.

Build Recommendations: 2″ 4 Ω 5 W Drivers

Two complete starting-point designs for the speakers used in this project, both targeting approximately 0.50 L — in the centre of the 0.3–0.6 L safe range for most cheap 2″ drivers. This gives a relaxed, extended bass roll-off that suits ambient drones well. The two designs handle the volume differently:

  • The 3D print is sized to 0.50 L directly. Polyfill is used only as a thin wall-damping coat (not to inflate the volume), giving a final acoustic volume of ~0.52 L.
  • The plywood box is sized to 0.41 L and relies on a heavier polyfill fill (+25%) to reach the same ~0.51 L acoustic target, because the smaller physical footprint suits the finger-joint construction and laser bed size.
Measure your driver first. Cheap 2″ drivers vary considerably. Before cutting anything, measure:
  • Cutout diameter — the hole the basket drops through. Typically 44–48 mm. The surround/flange must overhang the hole.
  • Flange diameter — the outer rim that sits on the baffle. Typically 58–65 mm. The baffle must have at least 6 mm of material beyond the flange edge.
  • Mounting bolt circle — diameter of the screw hole pattern. Mark and drill/cut pilot holes to match.

Dimension ratios 59:80:107 → 1 : 1.36 : 1.81 — non-harmonic. Same proportions as the plywood design, scaled up.

Why 0.5 L instead of 0.41 L + heavy stuffing: Polyfill has two independent effects: thermal compliance (makes the box seem larger) and acoustic absorption (damps internal reflections off the walls). For a 3D printed box you can size the cavity correctly from the start and use polyfill only for its absorption role — a thin wall coating rather than a half-filled box. The slight effective-volume increase from a light wall coat (~5–10%) takes you to around 0.52 L, comfortably within the target range. This is simpler and more predictable than relying on stuffing density to hit a volume target.

Print Two Pieces

  • Box body — closed on five sides, open on the front (90 mm × 117 mm face). Print open-face-down on the build plate: this orients the layer lines parallel to the largest stress direction and gives the best bed adhesion. Include a 4 mm diameter wire-exit hole in one rear corner, centred 8 mm from each edge.
  • Front baffle — 90 mm × 117 mm × 5 mm flat panel, printed separately. Speaker cutout and screw pilot holes go here (see placement below). Print flat on the bed for the best surface finish on the visible face.

Speaker Placement on Baffle

The baffle is 90 mm × 117 mm external. Centre the driver horizontally (45 mm from either side — 12.5 mm clearance to a 65 mm flange). Offset it 10 mm above vertical centre (68.5 mm from the bottom instead of 58.5 mm). This asymmetry breaks up diffraction from the baffle edges. Verify the driver flange sits at least 6 mm inside all four edges before cutting.

Polyfill — Wall Damping Only

The box is already the right size, so you do not need to fill it heavily. Polyfill here is acting purely as an acoustic absorber to damp reflections off the smooth plastic walls, not as a volume-increase medium.

  1. Pull polyfill into a loose cloud and press a 10–15 mm fluffy layer lightly against all five interior walls. Do not compress it flat — keep it light and airy. This is all the stuffing this box needs.
  2. Leave the central air volume mostly open. The box should feel substantially empty when you shake it.
  3. The thin wall layer adds a small effective-volume increase (~5–10%), putting the final acoustic volume at around 0.52 L — within the acceptable range for a typical cheap 2″ driver.

Assembly

  1. Thread the speaker wire through the wire-exit hole before stuffing.
  2. Apply the polyfill wall layer as described above.
  3. Solder or connect the speaker leads to the driver terminals.
  4. Seat the driver in the baffle cutout. Secure with M2.5 or M3 screws. Run a thin bead of cyanoacrylate (CA) glue around the driver surround where it meets the baffle for an airtight acoustic seal.
  5. Apply CA glue or 2-part epoxy around the full perimeter of the baffle-to-box-body joint. Press firmly and hold for 60 seconds. Any air gap here will degrade bass response.

Laminating the Baffle

Three layers of 3 mm ply glued together gives a 9 mm front baffle — stiff enough to hold the driver mounting screws reliably and resist vibration from the cone. Apply wood glue evenly to both faces of the middle layer, clamp all three together, and let cure for at least 2 hours before cutting the speaker hole. Once cured, the speaker cutout and pilot holes can be laser-cut through the full 9 mm stack in a single pass on a 40 W+ CO&sub2; laser (use multiple passes at lower power if needed to prevent charring). A 4.5 mm drill bit makes clean pilot holes post-lamination.

Speaker Placement on Baffle

Same geometry as the 3D-printed design: center horizontally (40.5 mm from edge on the 81 mm face), offset 10 mm above vertical centre (63 mm from the bottom on the 106 mm face). Verify the driver flange clears all edges by at least 6 mm before cutting.

Assembly Order

  1. Dry-fit all pieces — check that finger joints interlock snugly. Sand laser-scorched edges lightly; they are often slightly oversized on the tab faces.
  2. Assemble the four sides and back panel with wood glue. Finger joints provide mechanical alignment; add a small fillet of glue on the interior joint corners. Clamp and allow to cure fully (1–2 hours minimum).
  3. Seal all interior joints by running a bead of diluted PVA (1 part PVA, 1 part water) along every seam on the inside. Wood is porous — any joint gap is also an air leak.
  4. Add polyfill stuffing through the open front (same technique as Design 1, pressing a loose layer against the walls first, then filling the centre to ~50% by feel).
  5. Thread the speaker wire out through the rear exit hole.
  6. Mount the driver in the laminated baffle, securing with M3 screws and a CA bead around the surround for an air-tight fit.
  7. Glue the baffle to the box body last, applying wood glue around the full perimeter and clamping until set. This is the only seam you cannot reach from the inside afterward — clamp it carefully.
Finish tip: A coat of water-based polyurethane or shellac on the exterior seals the plywood against humidity (which causes the wood to swell and can crack glued joints over time). It also makes the box look intentional rather than prototype-ish.
