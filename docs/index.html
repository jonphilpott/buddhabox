BuddhaBox

A modular DSP framework for generative ambient audio on STM32

Architecture

BuddhaBox is a sample-by-sample modular DSP framework. Every sound-producing or sound-shaping module exposes a float process() method that returns one audio sample at a time. You compose patches by wiring outputs into inputs — just like patching a modular synthesizer with cables.

Signal Flow

The audio engine uses I2S DMA double-buffering. The DMA hardware continuously streams samples to the DAC. When it finishes one half of the buffer, it fires an interrupt and your audioCallback() fills that half with fresh samples while the other half plays.

Your DSP Code → audioCallback() → DMA Buffer → I2S Peripheral → UDA1334A DAC → Audio Out

Design Principles

Principle What It Means
Sample-by-sample Every module processes one sample per call. No block sizes to worry about when patching modules together.
Float internal, int16 output All DSP math uses float (-1.0 to +1.0). Conversion to 16-bit integers only happens at the final output stage.
Header-only modules DSP modules are defined entirely in .h files so the compiler can inline critical functions. Only the audio engine has a .cpp.
No dynamic allocation All memory is allocated at compile time via global objects and template parameters. No new or malloc in the audio path.
Composable Any module's output can feed into any other module's input. An LFO can modulate a filter, which filters an oscillator, which is shaped by an envelope.

AudioEngine audio_engine.h / .cpp

Namespace: AudioEngine

Configures I2S2 + DMA1 for continuous audio output to the UDA1334A. Double-buffered with half-complete and complete interrupts. You implement audioCallback() and call AudioEngine::begin().

Usage

// 1. Implement this function (called by DMA interrupt):
void audioCallback(int16_t* buffer, uint16_t length) {
    for (uint16_t i = 0; i < length; i += 2) {
        float sample = osc.process();
        int16_t s = (int16_t)(sample * 32000.0f);
        buffer[i]     = s;  // Left
        buffer[i + 1] = s;  // Right
    }
}

// 2. Start the engine in setup():
void setup() {
    AudioEngine::begin();
}

Functions

void AudioEngine::begin()
Initialize I2S + DMA and begin audio playback. Call once in setup().
void audioCallback(int16_t* buffer, uint16_t length)
User-implemented callback. Called by DMA interrupt ~172 times/sec.
buffer — int16_t* — stereo interleaved samples [L, R, L, R, ...]
length — uint16_t — number of int16_t values to fill (512 for 256 stereo frames)
ISR Rules: audioCallback runs in interrupt context. No Serial.print(), no analogRead(), no malloc/new. Keep computations minimal and predictable.

Composing New Modules

The BuddhaBox framework is designed to be composable: you build complex sounds by wiring simple modules together. Here's how to create your own reusable composite modules from the building blocks.

Pattern: Wrap Modules in a Class

The simplest approach is to create a class that holds the modules you need as members and exposes a process() method. This encapsulates the signal routing and parameter management.

Example: Filtered Oscillator

An oscillator with a built-in filter and LFO-modulated cutoff:

class FilteredOsc {
public:
    void setNote(uint8_t note) {
        osc_.setFrequency(midiToFreq(note));
    }

    void setFilterRange(float lo, float hi) {
        filterLo_ = lo;
        filterHi_ = hi;
    }

    void setLFORate(float hz) {
        lfo_.setFrequency(hz);
    }

    float process() {
        // LFO sweeps the filter cutoff
        float mod = lfo_.process();
        float cutoff = mapf(mod, -1.0f, 1.0f, filterLo_, filterHi_);
        filter_.setFrequency(cutoff);

        // Oscillator through filter
        filter_.process(osc_.process());
        return filter_.lowpass();
    }

private:
    Oscillator osc_;
    SVFilter filter_;
    LFO lfo_;
    float filterLo_ = 200.0f;
    float filterHi_ = 3000.0f;
};

Example: Enveloped Voice

A complete synth voice with oscillator + envelope + filter:

class SynthVoice {
public:
    void noteOn(uint8_t note) {
        osc_.setFrequency(midiToFreq(note));
        env_.gate(true);
    }

    void noteOff() { env_.gate(false); }

    bool isActive() { return env_.isActive(); }

    float process() {
        return osc_.process() * env_.process();
    }

private:
    Oscillator osc_;
    Envelope env_;
};

Example: Echo Unit

A reusable delay effect with controllable time and feedback:

class EchoUnit {
public:
    void setTime(float samples) { time_ = samples; }
    void setFeedback(float fb) { feedback_ = clampf(fb, 0.0f, 0.95f); }
    void setMix(float wet) { wet_ = wet; }

    float process(float input) {
        float delayed = delay_.read(time_);
        delay_.write(input + delayed * feedback_);
        return input * (1.0f - wet_) + delayed * wet_;
    }

private:
    DelayLine<8192> delay_;
    float time_ = 4000.0f;
    float feedback_ = 0.4f;
    float wet_ = 0.3f;
};

Key Principles

  • process() returns float: Keep the same pattern as built-in modules. Input and output are always float samples in [-1.0, +1.0].
  • Members not pointers: Declare sub-modules as member variables (not pointers). This avoids dynamic allocation and the compiler can inline method calls.
  • One sample at a time: Your process() should compute exactly one output sample per call, calling each sub-module's process() exactly once.
  • Expose only what's needed: Don't pass through every sub-module parameter. Expose high-level controls that make sense for the composite (e.g., noteOn instead of separate setFrequency + gate).
  • Watch your RAM: Each DelayLine uses significant RAM. Be mindful when composing modules that contain delay lines — check your build stats with pio run.

PatternSignal FlowResult
Series (chain)A → B → Cc.process(b.process(a.process()))

Examples

A. D Major Arpeggio — Plucked Sine

A simple sequencer that cycles through D–F#–A–D (D major triad over one octave) at 140 BPM eighth notes. Each note is shaped by a short envelope to create a plucked, bell-like quality.

TempoClock (140 BPM, eighths) → triggers Envelope → selects note Oscillator (sine) × Envelope → Output
// ── Example A: D Major Arpeggio with Plucked Sine ──

#include "audio_engine.h"
#include "oscillator.h"
#include "envelope.h"
#include "clock.h"
#include "midi_utils.h"

Oscillator osc;
Envelope env;
TempoClock clock(140.0f, 2);  // 140 BPM, eighth notes

// D major arpeggio: D4, F#4, A4, D5
const uint8_t arpeggio[] = {
    NOTE_C4 + 2,   // D4  (MIDI 62)
    NOTE_C4 + 6,   // F#4 (MIDI 66)
    NOTE_C4 + 9,   // A4  (MIDI 69)
    NOTE_C5 + 2    // D5  (MIDI 74)
};
const int arpLen = 4;

void audioCallback(int16_t* buffer, uint16_t length) {
    for (uint16_t i = 0; i < length; i += 2) {

        // On each clock tick, advance to the next arpeggio note
        if (clock.process()) {
            int step = clock.getTick() % arpLen;
            osc.setFrequency(midiToFreq(arpeggio[step]));
            env.trigger();  // Percussive: auto-releases after attack
        }

        // Sine oscillator shaped by the envelope
        float sample = osc.process() * env.process() * 0.6f;

        int16_t s = (int16_t)(clampf(sample, -1.0f, 1.0f) * 32000.0f);
        buffer[i]     = s;
        buffer[i + 1] = s;
    }
}

void setup() {
    osc.setWaveform(Waveform::SINE);
    osc.setAmplitude(1.0f);
    env.setAttack(0.002f);    // 2 ms — sharp pluck
    env.setRelease(0.3f);     // 300 ms — bell-like decay
    AudioEngine::begin();
}

void loop() { delay(10); }

B. Rain Simulation

Layered filtered noise that sounds like rainfall. Two pink noise sources are filtered at different frequencies: a low rumble (distant thunder/heavy drops) and a high patter (light rain on a surface). An LFO slowly modulates the high layer's brightness, simulating gusts of wind.

PinkNoise 1 → SVFilter (LP 300 Hz) → ╮ ├→ Mix → Output PinkNoise 2 → SVFilter (LP, swept) → ╯ ↑ LFO (tri, 0.07 Hz)
// ── Example B: Rain Simulation ──

#include "audio_engine.h"
#include "noise.h"
#include "filter.h"
#include "lfo.h"

PinkNoise rainLow(11111);
PinkNoise rainHigh(22222);
SVFilter filterLow;
SVFilter filterHigh;
LFO gustLFO;

void audioCallback(int16_t* buffer, uint16_t length) {
    for (uint16_t i = 0; i < length; i += 2) {
        // Layer 1: Low rumble
        filterLow.process(rainLow.process() * 0.4f);
        float rumble = filterLow.lowpass();

        // Layer 2: High patter — filter swept by LFO
        float cutoff = mapf(gustLFO.process(), -1.0f, 1.0f, 1500.0f, 6000.0f);
        filterHigh.setFrequency(cutoff);
        filterHigh.process(rainHigh.process() * 0.25f);
        float patter = filterHigh.lowpass();

        float rain = rumble + patter;
        int16_t s = (int16_t)(clampf(rain, -1.0f, 1.0f) * 32000.0f);
        buffer[i]     = s;
        buffer[i + 1] = s;
    }
}

void setup() {
    filterLow.setFrequency(300.0f);
    filterLow.setResonance(0.2f);
    filterHigh.setFrequency(3000.0f);
    filterHigh.setResonance(0.1f);
    gustLFO.setWaveform(Waveform::TRIANGLE);
    gustLFO.setFrequency(0.07f);
    AudioEngine::begin();
}

void loop() { delay(10); }

C. Tanpura-like Drone

A tanpura produces a shimmering, harmonically rich drone by plucking four strings that ring continuously. This version uses the KarplusStrong class. Four strings tuned to Pa–Sa–Sa–Sa (A3–D4–D4–D3) are re-plucked in sequence by a slow tempo clock.

TempoClock (50 BPM) → cycles through 4 strings, re-plucks each KarplusStrong[0] (A3) → ╮ KarplusStrong[1] (D4) → ├→ Mix → softclip → Output KarplusStrong[2] (D4) → ┤ KarplusStrong[3] (D3) → ╯
// ── Example C: Tanpura-like Drone using KarplusStrong ──

#include "audio_engine.h"
#include "karplus.h"
#include "clock.h"
#include "midi_utils.h"

KarplusStrong<1024> strings[4] = {
    KarplusStrong<1024>(111),  // Different seeds per string
    KarplusStrong<1024>(222),
    KarplusStrong<1024>(333),
    KarplusStrong<1024>(444)
};

TempoClock pluckClock(50.0f, 1);  // Slow, meditative

// Tanpura tuning: Pa, Sa, Sa, low Sa
const uint8_t tuning[] = {
    NOTE_C4 + 9,   // A3 — Pa (the fifth)
    NOTE_C4 + 2,   // D4 — Sa (the tonic)
    NOTE_C4 + 2,   // D4 — Sa (doubled)
    NOTE_C3 + 2    // D3 — low Sa
};

void audioCallback(int16_t* buffer, uint16_t length) {
    for (uint16_t i = 0; i < length; i += 2) {

        if (pluckClock.process()) {
            int which = pluckClock.getTick() % 4;
            strings[which].pluck(midiToFreq(tuning[which]));
        }

        float mix = 0.0f;
        for (int s = 0; s < 4; s++) {
            mix += strings[s].process() * 0.3f;
        }

        // Soft clip for gentle warmth
        mix = softclip(mix, 1.5f);

        int16_t out = (int16_t)(clampf(mix, -1.0f, 1.0f) * 32000.0f);
        buffer[i]     = out;
        buffer[i + 1] = out;
    }
}

void setup() {
    // Pluck all strings at startup
    for (int i = 0; i < 4; i++) {
        strings[i].pluck(midiToFreq(tuning[i]));
    }
    AudioEngine::begin();
}

void loop() { delay(10); }
Tip: To make the tanpura sound more authentic, try adding a very subtle pitch bend by slowly modulating the delay time with an LFO (±0.5 samples). Real tanpura strings have a characteristic "jivari" buzz caused by the string grazing the bridge — you can approximate this by increasing the damping slightly and using softclip() with a higher drive value.

Quick Start

Prerequisites

You need PlatformIO installed. Either:

  • VS Code with the PlatformIO IDE extension, or
  • PlatformIO CLI: pip install platformio

Build

# Clone or download the project, then:
cd buddhabox
pio run           # Compile the firmware

First build takes a minute or two (downloads the STM32 toolchain). Subsequent builds are fast (~2 seconds).

Upload

pio run -t upload  # Flash to the Black Pill via USB (DFU or ST-Link)
DFU Upload: To upload via the USB-C port (no ST-Link needed), hold the BOOT0 button, press and release NRST (reset), then release BOOT0. The board enters DFU mode. Then run pio run -t upload. You may need to add upload_protocol = dfu to platformio.ini.

Hardware Setup

Components

  • WeAct Studio Black Pill V2.0 (STM32F401CCU6)
  • UDA1334A I2S DAC breakout (e.g., Adafruit #3678 or generic)
  • 3.5mm audio jack or speaker/amplifier
  • Jumper wires
  • Optional: photoresistor + 10K resistor for light sensor

Wiring: Black Pill → UDA1334A

Black Pill Pin UDA1334A Pin Signal Description
PB12 WSEL LRCLK (Word Select) Toggles between left and right channels at 44.1 kHz
PB13 BCLK Bit Clock Clocks out individual data bits (32x sample rate)
PB15 DIN Data Serial audio data, MSB first, Philips I2S format
GND GND Ground Common ground reference
GND MUTE Mute Control Recommended: Tie to GND. While many modules have internal pull-downs, grounding this ensures the DAC is never accidentally muted by noise.
GND SF0/SF1 Format Select Recommended: Tie to GND for standard I2S. Floating usually defaults to I2S, but grounding prevents format switching from interference.
3V3 VIN Power 3.3V supply. Some UDA1334A boards accept 3.3–5V on VIN.
Note: Most CJMCU-1334 breakout boards require MUTE, SF0, and SF1 to be tied to GND for standard I2S operation.

Optional: Analog Sensor (e.g., Photoresistor)

3.3V ──┬── Photoresistor ──┬── PA0 │ │ └───── 10K Ω ───────┘ │ GND This voltage divider produces ~0V (dark) to ~3.3V (bright) on PA0, which the ADC reads as 0–4095.
I2S Pin Note: The I2S pins (PB12, PB13, PB15) are fixed by the STM32F401's internal peripheral routing — they map to the SPI2/I2S2 alternate function (AF5). If you need different pins, you'd need to use a different I2S peripheral (I2S3 uses different pins) and modify audio_engine.cpp.

Alternative DAC/Amp: MAX98357A (Mono)

The MAX98357A is an all-in-one I2S DAC and Class D Amplifier. It can drive a 4Ω or 8Ω speaker directly from the 5V USB power, making it ideal for a stand-alone BuddhaBox.

Black Pill Pin MAX98357A Pin Signal Description
PB12 LRC (WS) Word Select Standard I2S Word Select / LRCLK
PB13 BCLK Bit Clock Standard I2S Bit Clock
PB15 DIN Data Standard I2S Data
GND GND Ground Common ground reference
5V VIN Power 5V for maximum volume (3.3V also works but is quieter)
(Floating) SD SD_MODE Leave floating for (Left+Right)/2 mono mix
Power Tip: Add a large capacitor (470µF or higher) across the MAX98357A's VIN and GND to prevent voltage drops during loud peaks.
